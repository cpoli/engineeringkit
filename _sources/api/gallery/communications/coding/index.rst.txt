Coding

Channel codes: Hamming's block code, cyclic redundancy checks, and

    <div class="sphx-glr-thumbcontainer" tooltip="Frustrated by weekend computer runs aborted by a single bad relay, Richard Hamming (1950) designed codes that correct errors rather than merely detect them. In the (7,4) code three parity bits sit at positions 1, 2 and 4. When one bit flips, the failing parity checks, read as a binary number, give its position (~engineeringkit.communications.hamming74_encode, hamming74_decode). Any two codewords differ in at least three places (~engineeringkit.communications.hamming_distance), which is what makes single-error correction possible.">

    <div class="sphx-glr-thumbcontainer" tooltip="Peter Elias&#x27;s &quot;Coding for noisy channels&quot; showed that a code need not cut the data into blocks. A shift register of length K slides along the bit stream, and each input bit produces n output bits, sums modulo two of the register taps (~engineeringkit.communications.convolutional_encode). Elias proved that such codes are at least as good as block codes. Their strength is the free distance, the least weight of any path that leaves the all-zero state and returns to it (~engineeringkit.communications.convolutional_free_distance). For the standard rate-1/2 codes it grows with the constraint length.">

.. raw:: html

    <div class="sphx-glr-thumbcontainer" tooltip="W. Wesley Peterson and D. T. Brown showed how to detect errors with a few shift-register stages and exclusive-OR gates. Treat the message as a polynomial over GF(2), multiply by x^r, divide by a generator g(x) of degree r, and send the remainder after the message (~engineeringkit.communications.crc_encode). The receiver divides again and declares an error if anything is left (~engineeringkit.communications.crc_check). Every burst of r or fewer errors is caught, and a random error pattern slips through with probability 2^{-r}. CRCs now guard Ethernet frames, disks and USB packets.">

.. raw:: html

    <div class="sphx-glr-thumbcontainer" tooltip="Decoding a convolutional code by brute force means comparing the received sequence with all 2^L possible codewords. Andrew Viterbi saw that two paths entering the same encoder state at the same time have the same future, so only the better of them, the survivor, need be kept. The work then grows linearly with L (~engineeringkit.communications.viterbi_decode, returning a ViterbiDecodeResult). Viterbi introduced the algorithm as a device for proving error bounds. Jim Omura and David Forney showed in the early 1970s that it is maximum-likelihood decoding, and it became the decoder of deep-space links, GSM telephones and dial-up modems. Soft decisions, the received values before slicing, gain about 2 dB over hard bits.">
